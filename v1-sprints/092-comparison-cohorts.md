No historical test source or tolerance is edited in 092-A. All 383 original
outcomes remain in run 6 and run 7: 381 pass, two fail. The mapping's source hashes
refer to the clean run-7 dispatch. In a future device package, distinguish a
historical verifier run from the revised comparison contract in both collection
and judging. Never label a changed consumer case as the original test passing.
If an original verifier now disagrees with changed best/patience or memory semantics,
retain its result and explain the exact contract difference before a gate claim.

The two flagged nodes are the ordinary depth-zero forward/reverse conflict cases
at rate eight. Their historical caller literally tests `proposal.loss < state.loss`.
The new caller must instead consume a comparison of actual stored inputs. The
092-A enclosure rejects both captured mean trials as worsening, including rate
four that the historical predicate accepted. This is an explicit proposed
supersession of that numerical acceptance contract, supported by independent
mathematics. It does not rewrite either historical failure. The complete new
three-round trajectories and later coefficients are still unverified; the captured
round-zero proposals alone cannot establish their outcomes.

## Independent numerical cohort

[`normal_comparison_study.py`](../benchmarks/v1/normal_comparison_study.py) freezes
106 original-row comparisons before device execution:

- Twenty comparisons replay all ten observed run-7 trials against both training
  and validation, with source-trace hashes and exact stored input values.
- Five declared analytic cases distinguish tiny true improvement, cancellation,
  unchanged raw, clear worsening and unsupported exponent range.
- Eighty-one actual candidate arrays come from the existing independent CPU
  original-row oracle on `weighted` and `d2`, one round at depth one, rate eight,
  joint/forward/reverse updates and ordinary/Fisher/damped geometry. D2 retains its
  cohort minimum. These are CPU proposals, not emulated CUDA trajectories or an
  independently authored extension. The original decision is retained alongside
  the new comparison; this does not rerun the trajectory under revised acceptance.

Each entry retains the before/after raw, target, offset and weight values and
their exact binary64 representations; original float32 bits remain in the hashed
source traces. Promotion changes no input value. Entries also retain the
enclosure/status/reason, both 60/100-digit loss differences and higher precision
where required. Assertions compare against those original-row expressions.
Additional tests cover input/domain rejection, subnormals, weight rescaling,
permutation, exact storage rounding and seeded whole-row enclosure checks. No
tolerance changes after device observations are allowed.
